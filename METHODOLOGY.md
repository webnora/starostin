# Методология анализа: NLP-pipeline для семантической кластеризации глагола

## Обзор

Для выявления семантической структуры глагола "делать" в германских языках применялась **цепочка методов** (pipeline) из области компьютерной лингвистики и NLP (Natural Language Processing):

```
Корпус → Извлечение контекстов → TF-IDF → HDBSCAN → UMAP → Интерпретация
```

Ниже описано rationale (обоснование) каждого этапа.

---

## 1. TF-IDF векторизация контекстов

### Что это такое?

**TF-IDF** (Term Frequency — Inverse Document Frequency) — метод векторного представления текстов, который:
- **Учитывает частотность слов** в каждом контексте (TF)
- **Понижает вес общеупотребительных слов** (IDF)
- **Выделяет уникальные слова** для каждого контекста

Математически для слова *t* в контексте *d*:

```
TF-IDF(t, d) = TF(t, d) × IDF(t)

где:
TF(t, d) = количество вхождений t в d / общее количество слов в d
IDF(t) = log(общее количество контекстов / количество контекстов с t)
```

### Почему выбрана TF-IDF?

1. **Интерпретируемость** — лингвист может понять, какие слова важны (высокий TF-IDF)
2. **УчетRare words** — уникальные лексемы получают больший вес
3. **Работа с морфологией** — не требует лемматизации (важно для древних языков)
4. **Разреженность** — создаёт разреженные векторы (efficient storage)

### Параметры TF-IDF (наши настройки)

```python
TfidfVectorizer(
    max_features=150,    # Количество признаков (словарь)
    min_df=2,            # Мин. частотность слова (min document frequency)
    token_pattern=r"[...]" # Регулярное выражение для токенизации
)
```

**Объяснение параметров:**

| Параметр | Значение | Лингвистический смысл |
|----------|----------|----------------------|
| **max_features=150** | 150 слов | Используем только топ-150 слов по частотности. Это уменьшает шум и ускоряет кластеризацию. |
| **min_df=2** | 2+ контекста | Слово должно встречаться минимум в 2 контекстах. Убираем уникальные hapax legomena. |
| **token_pattern** | Регулярное выражение | Учитываем только буквенные токены, включая специальные символы древних языков (ð, þ, æ, ø). |

**Почему min_df=2?**
- Слова, встречающиеся 1 раз (hapax legomena), не информативны для кластеризации
- Они создают шум (" Curse of dimensionality")
- Но min_df=1 теряет слишком много информации

**Результат:** матрица размером `(n_contexts, 150)`, где каждая строка — числовой вектор контекста.

## 2. HDBSCAN кластеризация

### Что это такое?

**HDBSCAN** (Hierarchical Density-Based Spatial Clustering of Applications with Noise) — алгоритм кластеризации, который:
- **Находит плотные области** в пространстве признаков
- **Не требует фиксированного числа кластеров** (в отличие от K-Means)
- **Выделяет шум** (outliers) — контексты, не подходящие ни к одному кластеру
- **Работает иерархически** — строит дерево кластеров

### Почему выбран HDBSCAN (а не K-Means)?

| Метод | Преимущества | Недостатки |
|-------|-------------|------------|
| **K-Means** | Быстро, просто | Требует фиксированное k; создает круглые кластеры; нет шума |
| **HDBSCAN** | Адаптивное число кластеров; выделяет шум;任意 формы кластеров | Медленнее; чувствителен к параметрам |

**Для нашей задачи:**
- ✅ Мы **не знаем заранее**, сколько семантических кластеров у don/tuon
- ✅ Многие контексты уникальны → HDBSCAN пометит их как **noise**
- ✅ Семантические кластеры **не обязательно круглые** в пространстве TF-IDF

### Параметры HDBSCAN

```python
hdbscan.HDBSCAN(
    min_cluster_size=8,   # Минимальный размер кластера
    min_samples=3,        # Плотность кластера
    metric='euclidean',   # Метрика расстояния
    cluster_selection_method='eom'  # Метод выделения кластеров
)
```

**Объяснение параметров:**

| Параметр | Значение | Лингвистический смысл |
|----------|----------|----------------------|
| **min_cluster_size** | 8–15 контекстов | Минимальный размер семантической группы. Меньше = больше мелких кластеров. |
| **min_samples** | 2–3 контекста | Чем меньше, тем более плотные кластеры выделяются. Защита от одиночных outliers. |
| **metric='euclidean'** | Евклидово расстояние | Стандартное расстояние между векторами TF-IDF. Альтернативы: cosine, manhattan. |
| **cluster_selection_method='eom'** | Excess of Mass | Стратегия выделения кластеров из иерархического дерева. |

**Почему min_cluster_size варьируется?**

| Корпус | Размер | min_cluster_size | Обоснование |
|--------|--------|------------------|-------------|
| OE lemmas.txt (74) | Малый | 4 | Не можем делать крупные кластеры |
| Calgary (220) | Средний | 8 | Баланс между детальностью и надежностью |
| MHG (939) | Большой | 10 | Позволяет найти устойчивые паттерны |

**Адаптивность:**
```
Малый корпус → меньший min_cluster_size → больше кластеров
Большой корпус → больший min_cluster_size → устойчивые кластеры
```

### Результат кластеризации

Для каждого контекста получаем **label**:
- `0, 1, 2, ...` — номер кластера
- `-1` — шум (не классифицирован)

**Распределение (пример Calgary):**
- Кластер 0: 16 контекстов (сравнения)
- Кластер 1: 9 контекстов (религиозные)
- ...
- Шум (-1): 155 контекстов (70.5%)

## 3. UMAP визуализация

### Что это такое?

**UMAP** (Uniform Manifold Approximation and Projection) — алгоритм **снижения размерности** (dimensionality reduction), который:
- **Проецирует** данные из многомерного пространства (150 признаков TF-IDF) в 2D
- **Сохраняет** глобальную структуру данных (лучше, чем t-SNE)
- **Быстр** на больших корпусах
- **Создаёт** визуальную карту кластеров

### Почему UMAP (а не t-SNE, PCA)?

| Метод | Преимущества | Недостатки |
|-------|-------------|------------|
| **PCA** | Очень быстро; интерпретируем | Линейный; плохо сохраняет структуру |
| **t-SNE** | Отлично сохраняет локальную структуру | Медленно; теряет глобальную структуру |
| **UMAP** | Сохраняет и глобальную, и локальную структуру; быстр | Параметрический |

### Параметры UMAP

```python
umap.UMAP(
    n_neighbors=15,      # Локальный vs глобальный баланс
    min_dist=0.1,        # Распределение точек
    n_components=2,      # Размерность пространства (2D для визуализации)
    metric='euclidean',  # Метрика (должна совпадать с HDBSCAN!)
    random_state=42      # Воспроизводимость
)
```

**Объяснение параметров:**

| Параметр | Значение | Лингвистический смысл |
|----------|----------|----------------------|
| **n_neighbors** | 10–15 | Баланс между локальной и глобальной структурой. Меньше = фокус на локальных кластерах. |
| **min_dist** | 0.1 | Минимальное расстояние между точками. Меньше = более плотные кластеры на графике. |
| **n_components=2** | 2D | Пространство для визуализации (X, Y координаты). |
| **random_state=42** | Фиксированный seed | Воспроизводимость результатов. |

### Результат UMAP

Каждый контекст получает **2D координаты** `(x, y)`, которые отрисовываются на scatter plot:
- Цвет = номер кластера
- Серый цвет = шум
- Близкие точки = похожие контексты семантически

**Пример интерпретации:**
- Кластеры сгруппированы → устойчивая семантическая зона
- Разрозненные точки → шум, уникальные контексты
- Перекрытие кластеров → нечеткие границы семантики

## 4. Почему именно такая комбинация?

### Pipeline: TF-IDF → HDBSCAN → UMAP

```
Текст → Вектор (TF-IDF) → Кластеры (HDBSCAN) → Визуализация (UMAP)
  1D        150D                 1D                    2D
```

### Обоснование выбора методов

1. **TF-IDF (не Word Embeddings)**
   - ✅ Интерпретируемость (лингвист видит топ-слова)
   - ✅ Работает на малых корпусах (Word2Vec требует больших данных)
   - ✅ Не требует предварительного обучения (нет моделей для древних языков)

2. **HDBSCAN (не K-Means)**
   - ✅ Не требует знать число кластеров заранее
   - ✅ Выделяет шум (важно для широкозначных глаголов)
   - ✅ Естественные кластеры (не искусственные разделения)

3. **UMAP (не PCA/t-SNE)**
   - ✅ Сохраняет структуру лучше, чем PCA
   - ✅ Быстрее, чем t-SNE
   - ✅ Показывает глобальную картину кластеров

### Сравнение с альтернативами

| Pipeline | Преимущества | Недостатки |
|----------|-------------|------------|
| **TF-IDF + HDBSCAN + UMAP** | Интерпретируемость; адаптивность; работа на малых корпусах | Потенциальная потеря информации при TF-IDF |
| Word Embeddings + K-Means | Учет семантической близости слов | Требует больших корпусов; менее интерпретируем |
| LDA (тематическое моделирование) | Вероятностное распределение тем | Сложнее интерпретация; требуется фиксировать число тем |

Большой корпус (939) → низкий шум (32.1%) → больше данных, устойчивые кластеры

1. **Размер** — сколько контекстов (абсолютно и %)

3. **10 случайных контекстов** — примеры употребления

**Пример интерпретации (MHG Кластер 1):**

## 6. Ограничения методологии

### TF-IDF
- ❌ Игнорирует порядок слов (bag-of-words)
- ❌ Не учитывает синтаксис
- ❌ Потенциальная потеря морфологической информации

### HDBSCAN
- ❌ Чувствителен к параметрам (min_cluster_size)
- ❌ На малых корпусах может дать все как шум
- ❌ Разные запуски могут дать разные результаты (если не зафиксирован seed)

### UMAP
- ❌ Визуализация может быть искажена (projection artifacts)
- ❌ 2D потеря информации из 150D
- ❌ Требуется настройка параметров для каждого корпуса
